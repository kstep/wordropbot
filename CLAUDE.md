# wordropbot

Telegram-бот для запоминания слов. Пользователи собирают общие коллекции слов с переводами, подключаются к ним по коду, а бот по личному расписанию присылает квизы с вариантами ответа. Слова, на которых чаще ошибаются, попадаются чаще.

Стек: Rust 2024 (stable), tokio, teloxide 0.17, sqlx 0.9 на SQLite, chrono, humantime, clap. Конфигурация в TOML, установка через systemd (`deploy/`).

## Безопасность

- В `config.toml` лежит настоящий токен бота. Файл не читать целиком, не выводить и не коммитить. Путь к базе можно узнать так: `grep -E '^\s*path' config.toml`.
- Не запускать бинарник с этим конфигом без просьбы владельца. Субагентам запрещено читать `config.toml`.
- `wordropbot.db` содержит данные владельца. Это не тестовая база, удалять или пересоздавать её нельзя.

## Проверка

Перед каждым коммитом:

```sh
cargo +nightly fmt --check && cargo test && cargo clippy --all-targets -- -D warnings
```

Форматирование только через `cargo +nightly fmt`, настройки в `rustfmt.toml`. Тулчейн закреплён на stable в `rust-toolchain.toml`, а версия Rust по умолчанию на машине старая.

## Устройство

- `src/main.rs`: запуск, сигналы и ограниченная по времени остановка.
- `src/bot/`: Telegram.
  - `handlers.rs`: обработчики команд и кнопок, `View`.
  - `texts.rs`: тексты сообщений и `LimitedWriter`, который обрезает сообщение по пределу Telegram прямо при записи.
  - `command.rs`: разбор команд и `MENU` для меню по `/`.
  - `callback.rs`: данные кнопок.
  - `gate.rs`: очередь обновлений одного пользователя.
  - `limiter.rs`: ограничение попыток подключения.
  - `page.rs`: страницы.
- `src/service.rs`: выбор и отправка квиза. Выбор слова выполняется вне async-потоков, с ограничением параллелизма.
- `src/scheduler.rs`: периодический обход пользователей, у которых наступил срок.
- `src/storage/`: все SQL-запросы. Пределы на данные проверяются в той же транзакции, что и запись.
- `src/selection.rs`: вес слова по истории ответов с затуханием.
- `src/import.rs`: разбор строк «слово перевод» и `NormalizedText` для сравнения.
- `migrations/`: схема. База уже содержит данные, поэтому существующие миграции не менять, а добавлять новые файлы.

## Правила кода владельца

- **Типы.**
  - Доменные значения получают типы с определённой семантикой, а не примитивы.
  - Разбор строк делается через `FromStr`.
  - Логика живёт в методах и associated functions, а не в свободных функциях.
  - Для типовых задач берутся готовые крейты.
- **Имена.**
  - Имена типов это существительное или прилагательное с существительным, но не голое прилагательное (`LimitedWriter`, а не `Truncating`).
  - В идентификаторах, включая имена тестов, нет артиклей `a`, `an`, `the`.
  - Переменные называются полными словами: `error`, а не `e`.
- **Без одноразовых типов.** Тип, который создаётся только ради одного вызова метода, заменяется методом существующего типа или функцией.
- **Без оверинжиниринга.** Не нужны постобработка, проверки на всякий случай и обходные механизмы там, где задачу решает прямой код.
- **Без лишних аллокаций.** Нельзя делать `collect`, а затем ещё одно преобразование, а также `format!` ради конкатенации, повторные проходы по строке и клонирование там, где хватает ссылки.
- **Беззнаковые типы** для значений, которые не бывают отрицательными: счётчиков, страниц, периодов. `i64` остаётся только для rowid SQLite и идентификаторов Telegram.
- **Зависимости** берутся последних версий: проверять на crates.io, а не по памяти.
- **Стиль.**
  - Переменные подставляются прямо в строку форматирования: `"{value}"`.
  - Импорты стоят в начале модуля.
  - Тип указывается у `let`, а не через turbofish.
  - Комментарии пишутся на английском и только о неочевидном «почему».

## Устройство, о котором легко забыть

- Время хранится как `DateTime<Utc>` текстом RFC 3339, так его пишет `sqlx`. Строки в UTC сравниваются в SQL в правильном порядке, это закрепляет тест `due_check_orders_fractional_seconds`. Период не длиннее года, поэтому прибавление к текущему времени не переполняется.
- Код коллекции выделяется моноширинным через `View::push_code`, то есть сущностью `code` в момент записи, а не HTML-разметкой.
- Тексты пользователю пишутся на русском. Для греческого важны ударения и конечная сигма, поэтому `NormalizedText` переводит в нижний регистр всю строку целиком.

## Работа

- Готовую проверенную работу коммитить сразу, не спрашивая. Не пушить без просьбы.
- Сообщение коммита: тема до 72 символов, тело не длиннее 10 строк. Писать его в файл и коммитить через `git commit -F`, так требует хук.
- `docs/` с локальной спецификацией и планом коммитит сам владелец.
